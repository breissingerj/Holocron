# Claude CLI Harness Validation Playbook

Validates that the Claude Code harness has every Holocron component correctly wired.
Run this manually after `install.sh`, after any symlink changes, or when Claude Code
behavior seems off.

**Rewritten 2026-09-01 (spec 001 follow-up)** for the single-harness Claude Code + pi
layout: CLAUDE.md is a generated concatenation (no `@`-imports), skills/agents are
real merge-linked directories rather than top-level symlinks, and hook checks are
read dynamically from `settings.json` instead of a hardcoded `~/.config/opencode/`
path list. This playbook checks Claude-specific content correctness (import
resolution, hook wiring, MCP registration) that `install.sh --check` doesn't cover;
for machine-wide pointer drift (skills, agents, instructions, settings precedence),
run `install.sh --check` first.

---

## How to run

Each check is a bash one-liner. Run them in order. A ✓ means pass; a ✗ means fix
required — the remedy is listed inline.

```bash
bash $HOLOCRON_REPO_ROOT/claude/validate-claude-cli.sh
```

Or run checks manually section by section below.

## Section 1 — Core config files

### 1.1 CLAUDE.md exists and is a symlink to the Holocron repo

```bash
[[ -L ~/.claude/CLAUDE.md ]] \
  && echo "✓ CLAUDE.md is a symlink" \
  || echo "✗ CLAUDE.md missing or not a symlink — run install.sh"
```

### 1.2 CLAUDE.md symlink resolves (target exists)

```bash
[[ -f ~/.claude/CLAUDE.md ]] \
  && echo "✓ CLAUDE.md target exists" \
  || echo "✗ CLAUDE.md symlink is broken — check Holocron/claude/CLAUDE.md"
```

### 1.3 CLAUDE.md has the GENERATED header

CLAUDE.md is a **generated concatenation** (`instructions/AGENTS.md` + `claude/claude-tail.md`
+ primed `memory/MEMORY.md`), not a hand-written `@`-import shim — Claude's
external-`@`-import consent gate made a hand-written shim unreliable across new
projects (see `DECISIONS.md` / `research.md` R1). It is git-ignored and regenerated
by `install.sh` on every run.

```bash
grep -q "^<!-- GENERATED by install.sh" ~/.claude/CLAUDE.md \
  && echo "✓ CLAUDE.md has the GENERATED header" \
  || echo "✗ CLAUDE.md missing the GENERATED header — stale copy or hand-edited?"
```

### 1.4 settings.json exists and is a symlink

```bash
[[ -L ~/.claude/settings.json ]] \
  && echo "✓ settings.json is a symlink" \
  || echo "✗ settings.json missing or not a symlink — run install.sh"
```

### 1.5 settings.json is valid JSON

```bash
python3 -m json.tool ~/.claude/settings.json > /dev/null 2>&1 \
  && echo "✓ settings.json is valid JSON" \
  || echo "✗ settings.json is invalid JSON"
```

## Section 3 — Skills and commands

`skills/` and `agents/` are **merge-linked real directories** — a whole-dir symlink
per skill, a per-file symlink per agent — not top-level symlinks themselves. Only
`commands/` and `instructions/` are still plain directory symlinks.

### 3.1 skills/ is a real directory (not a symlink itself)

```bash
[[ -d ~/.claude/skills && ! -L ~/.claude/skills ]] \
  && echo "✓ ~/.claude/skills is a real directory (merge-linked)" \
  || echo "✗ ~/.claude/skills missing or still a symlink — run install.sh"
```

### 3.2 At least one skill directory is present

```bash
SKILL_COUNT=$(find ~/.claude/skills -maxdepth 1 -mindepth 1 2>/dev/null | wc -l | tr -d ' ')
[[ "$SKILL_COUNT" -gt 0 ]] \
  && echo "✓ $SKILL_COUNT skill(s) found in ~/.claude/skills/" \
  || echo "✗ No skills found — check ~/.claude/skills/"
```

### 3.3 All skill names are lowercase-hyphen (Agent Skills standard)

```bash
find ~/.claude/skills -maxdepth 1 -mindepth 1 2>/dev/null | xargs -n1 basename | grep -Ev '^[a-z0-9-]+$' \
  && echo "✗ non-compliant skill name(s) found above (should be lowercase-hyphen)" \
```

### 3.4 commands/ is a symlink

## Section 4 — Agents

Claude Code reads subagents from `~/.claude/agents/`. Holocron maintains one
canonical set of Claude Code schema agent files at `agents/` (top-level, spec 001 —
the old `claude/agents/` + `opencode/agents/` dual-maintenance pair is retired),
symlinked here by `install.sh`.

### 4.1 agents/ exists as a real directory (merge-linked)

```bash
[[ -d ~/.claude/agents && ! -L ~/.claude/agents ]] \
  && echo "✓ ~/.claude/agents is a real directory (merge-linked)" \
  || echo "✗ ~/.claude/agents missing or still a symlink — run install.sh"
```

### 4.2 At least 15 agents present

```bash
AGENT_COUNT=$(ls ~/.claude/agents/*.md 2>/dev/null | wc -l | tr -d ' ')
[[ "$AGENT_COUNT" -ge 15 ]] \
  && echo "✓ $AGENT_COUNT agents found" \
  || echo "✗ Expected 15+, found $AGENT_COUNT — check the repo agents/ directory"
```

### 4.3 No dangling agent symlinks

`install.sh`'s per-source convergence doesn't scan the destination for orphans that
no longer match any source file (e.g. an agent deleted from `agents/`, or — the
concrete case found 2026-09-01 — two leftover links to the retired private agents
from before T008 was dropped). `merge_link_agents()` now cleans these up on every
`install.sh` run, but check directly too:

```bash
DANGLING=0
for f in ~/.claude/agents/*.md; do [[ -e "$f" ]] || DANGLING=$((DANGLING+1)); done
[[ "$DANGLING" -eq 0 ]] \
  && echo "✓ no dangling agent symlinks" \
  || echo "✗ $DANGLING dangling agent symlink(s) — run install.sh"
```

## Section 6 — Hook scripts

Reads every hook command actually wired in `settings.json` and verifies each
referenced script file exists (and, for bash scripts, is executable) — rather than
a hardcoded list at the retired `~/.config/opencode/scripts/hooks/` path. Most
production hooks are private TypeScript files in `$HOLOCRON_MEMORY_DIR/hooks/`
(`*.hook.ts`); the public repo's `claude/scripts/hooks/*.sh` are the shareable
Claude-native equivalents of the old OpenCode plugins — currently only
`memory-feed.sh` is wired in live (added 2026-09-01; the OpenCode plugin it
replaces was deleted with the rest of `opencode/`).

```bash
python3 <<'PYEOF'
import json, os, re

d = json.load(open(os.path.expanduser("~/.claude/settings.json")))
hooks = d.get("hooks", {})
seen = set()
for event, entries in hooks.items():
    for entry in entries:
        for h in entry.get("hooks", []):
            cmd = h.get("command", "")
            if not cmd or cmd in seen:
                continue
            seen.add(cmd)
            m = re.search(r'([~$][^\s]*\.(?:sh|ts))', cmd)
            if not m:
                continue
            path = os.path.expandvars(m.group(1).replace("~", os.path.expanduser("~")))
            if not os.path.isabs(path):
                continue
            if not os.path.isfile(path):
                print(f"✗ {event}: hook script missing: {path}")
            elif path.endswith(".sh") and not os.access(path, os.X_OK):
                print(f"✗ {event}: hook script not executable: {path}")
            else:
                print(f"✓ {event}: {os.path.basename(path)} OK")
PYEOF
```

## Known gaps vs. OpenCode (historical)

OpenCode itself is retired (spec 001), but these capability gaps were never
closed when the Claude-native hook equivalents were built, and remain true today
— not failures, just documented limitations of Claude Code's hook model:

| Capability | OpenCode (retired) | Claude Code |
|---|---|---|
| Live response scanning (Ralph Loop) | Full | PRD-state stop-guard only |
| Context injection timing | Pre-response (plugin) | Post-session-start (hook) |
| Programmatic follow-up injection | Yes (`tui.submitPrompt`) | Not possible |
